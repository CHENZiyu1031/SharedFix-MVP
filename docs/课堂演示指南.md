# SharedFix 课堂演示指南

打开已发布的浏览器版地址即可开始。每个浏览器标签页都有自己的演示进度，刷新页面或点击 **Reset demo** 可以从头练习。使用 Windows 本地 Node.js 版时，双击项目目录里的 `start.cmd` 并保留启动窗口。

三个场景各运行一条独立的 EVM 测试链。页面的余额、订单状态和交易回执都来自实际执行的 Solidity 合约。mUSDC 是有六位小数的模拟代币，演示使用测试账户。

## 原型回答什么问题

三家买方分别承诺 4,000、3,000 和 3,000。期限内全部到账，订单才生效。维护者提交版本和验收材料的摘要，两位不同的买方评审确认后进入异议期。无人提出异议且期限结束后，维护者可领取 9,500，平台可领取 500。如果筹资截止时只有 7,000，已付款的买方各自领回原款，每笔只能领一次。

钱包连接器升级是课堂案例。企业在订单里可以要求验证多钱包发现、不同加载顺序和用户选中钱包后的连接。`order-terms.json` 是样例条款，`example-delivery.json` 是示例交付材料，均在本指南所在目录。合约记录这两个文件的 Keccak-256 摘要，并记录交付版本名称的摘要。评审可以据此核对材料是否与提交时相同。判断测试结果是否合格由指定评审负责，本案例只演示合约如何处理他们的决定。

## 90 秒演示

上台前在 `Fund & settle` 和 `Expire & refund` 两页，各用 A 和 B 存好 4,000 和 3,000。两页都应显示 7,000 / 10,000。保留已经发生的交易回执，方便评委看清起点。用英文讲即可，中文供排练。

| 时间 | 屏幕操作 |
| --- | --- |
| 0–20 秒 | 打开 `Fund & settle`，用 C 存入 3,000。指出筹资从 7,000 到 10,000，订单才生效。 |
| 20–55 秒 | 点击 `Submit delivery as maintainer`，再由 A、B 分别批准。点击 `Advance past challenge period`，说明这是推进本地测试链时钟。领取维护者的 9,500 和平台的 500，指向收款后余额。 |
| 55–90 秒 | 切到 `Expire & refund`，指出 C 没有存款。点击 `Advance past funding deadline` 后，用 A 领取 4,000，再点 `Try A’s refund again` 查看拒绝结果。B 领回 3,000 后，合约余额应为零。 |

**English script**

> SharedFix lets three companies jointly order an open source upgrade. Buyers A and B have put in seven thousand test tokens. Watch what happens when buyer C adds its three thousand. The full budget is now in escrow and the order becomes active.
>
> The maintainer submits the release and a sample acceptance report. Two buyers approve the same delivery. I’m advancing the clock on our local test chain to the end of the challenge period. The maintainer now claims nine thousand five hundred, and SharedFix claims five hundred.
>
> In this second order, buyer C never funds its share. The deadline passes with only seven thousand in escrow. Buyer A claims four thousand, and the contract rejects another attempt to claim the same refund. Buyer B can recover its three thousand as well.

**中文对照**

> SharedFix 让三家公司联合采购一次开源升级。A 和 B 已经存入七千测试代币。现在 C 补上三千，预算全部进入托管，订单终于可以生效。
>
> 维护者提交交付版本和一份示例验收报告。两家买方批准同一份交付。我现在推进本地测试链的时钟，好让大家看到异议期结束后的结果。维护者领取九千五百，SharedFix 领取五百。
>
> 第二笔订单里，C 一直没有出资。到期时托管账户只有七千。A 领回四千，再领一次时合约拒绝。B 也可以领回自己的三千。

**答辩备选场景**　在 `Independent review` 中筹足资金、提交交付，保留不足两票的审批，再推进至评审期限结束。此时主复核人可以接手。如果主复核人逾期未处理，继续推进到备用复核窗口。两人都逾期时，订单进入退款状态。复核人只决定按原约定付款还是退款，收款地址在订单创建时已固定。

## Base Sepolia 交接

当前演示运行在本地 EVM，页面回执只对应本地链。若后续完成 Base Sepolia 部署，可以提交该测试网的合约地址与区块浏览器交易链接。

1. 准备独立的测试钱包角色。将浏览器钱包切到 Base Sepolia，链 ID 为 `84532`、RPC 为 `https://sepolia.base.org`。部署账户和需要发交易的角色从官方文档列出的水龙头领取测试 ETH，供支付测试网手续费。[连接 Base](https://docs.base.org/get-started/connect-to-base) · [领取测试 ETH](https://docs.base.org/get-started/get-funds)
2. 在 Remix 导入 `contracts/MockUSDC.sol` 和 `contracts/SharedFixOrder.sol`，用 Solidity `0.8.30` 编译。在 `Deploy & Run` 选择 `Browser Extension`，确认钱包显示 Base Sepolia，再部署 `MockUSDC`。用模拟币的发行账户给 A、B、C 分别铸造约定的测试余额。[Remix 部署文档](https://remix-ide.readthedocs.io/en/latest/run.html)
3. 部署订单时按合约参数顺序填入模拟代币地址、三个买方地址、三个份额、维护者、平台、主复核人和备用复核人，再填写筹资、交付、评审、异议和每名复核人的期限，单位为秒。最后填入条款文件的 Keccak-256 摘要。如果为录屏缩短测试期限，先更新相应的条款文件，再计算摘要。六位小数下，`4000 / 3000 / 3000` 对应整数 `[4000000000,3000000000,3000000000]`。用每位买方的账户，在模拟代币合约调用 `approve(订单地址, 自己的份额)`，授权后再调用订单的 `deposit()`。
4. 分别准备已筹满和只筹到 7,000 的两笔订单。公开测试网使用真实区块时间，为演示准备短期测试参数或提前等订单到期，并在演示中说明。用 Base Sepolia 浏览器查看存款、验收、付款和退款交易，记录部署地址及关键交易链接。[Base 网络和浏览器](https://docs.base.org/get-started/connect-to-base)
